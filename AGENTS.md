# ts-in-types

The TypeScript 7 compiler (tslua, a Lua 5.4 port of typescript-go) running
inside the TypeScript type checker (tsrs), on lua-in-types v2 (Lua compiled
ahead of time to type aliases). Read `docs/PLAN.md` first, then
`vendor/lua-in-types/docs/AOT.md`.

## Repos

- `vendor/lua-in-types`: submodule, URL `../lua-in-types` (the sibling
  checkout `/Users/gabrielperez/Documents/lua-in-types` is canonical). General
  Lua work (front end, IR, reference, type runtime, emitter) is committed
  there, on its `main`, never inside the submodule checkout. Then bump the
  submodule here:
  `git -c protocol.file.allow=always submodule update --remote vendor/lua-in-types`
  and commit the pointer (`chore: bump lua-in-types`).
- `vendor/tslua`: submodule, github.com/Yhozen/tslua pinned to a commit. Read
  only. If tslua needs a change to run on lua-in-types, patch it with an
  overlay module under `lua/` (loaded before the original), never edit the
  submodule.
- Import lua-in-types code by relative path
  (`../vendor/lua-in-types/src/aot/...`).

## Rules

- Conventional Commits; end messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never push and never add remotes.
- "In types" means tsrs (`tsrs`, `TSRS_FAST=1`); no tsc or tsgo benchmarks.
- Generated files are marked as such and regenerated by a script, never edited
  by hand.
- Keep scratch files in `.run/` (git-ignored).
- Before committing: `vp check --fix`, `vp run check`, `vp test`.

## The oracle (P1)

tslua under real Lua 5.4 (wasmoon) is the ground truth.

- `lua/tsc.lua`: the harness, `check(files, args) -> output, status`.
  Deterministic and free of io/os/debug/load/coroutines; it must also run on
  the lua-in-types reference interpreter and in the types.
- `scripts/tslua.ts`: runs a check in a fresh wasm instance. Instruction counts
  are exact (count hook of 1) and reproducible only because `Date.now` is
  frozen (Lua's string hash seed) and the instance is fresh with emscripten's
  `_` variable pinned (heap addresses decide `pairs` order over table keys).
  Outputs never depended on either.
- `vp run oracle` rewrites `oracle/expected/` and `oracle/manifest.json`;
  `vp run oracle -- --verify` reruns and compares outputs and counts.
- `vp run upstream` reselects `oracle/inputs/upstream/` (TypeScript cases);
  `vp run census` -> `docs/CENSUS.md`; `vp run profile` -> `docs/PROFILE.md`
  and `oracle/profile.json`; `vp run tower` -> `oracle/tower.json`; `vp run warmup` -> `oracle/warmup.json`.
- `oracle/inputs/**` is `-text` in `.gitattributes`: upstream cases keep their
  CRLF line endings byte for byte.
