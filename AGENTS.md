# ts-in-lua-in-types

The TypeScript 7 compiler (tslua, a Lua 5.4 port of the Go compiler, typescript-go,
now microsoft/TypeScript) running
inside the TypeScript type checker (tsrs), on lua-in-types v2 (Lua compiled
ahead of time to type aliases). Read `docs/PLAN.md` first, then
`vendor/lua-in-types/docs/AOT.md`.

## Repos

- `vendor/lua-in-types`: submodule, URL `../lua-in-types` (the sibling
  checkout `/Users/gabrielperez/Documents/lua-in-types` is canonical). General
  Lua work (front end, IR, reference, type runtime, emitter) is committed
  there, on its `main`, never inside the submodule checkout. Then bump the
  submodule here:
  `git -c protocol.file.allow=always submodule update --remote vendor/lua-in-types`
  and commit the pointer (`chore: bump lua-in-types`).
- `vendor/tslua`: submodule, github.com/Yhozen/tslua pinned to a commit. Read
  only. If tslua needs a change to run on lua-in-types, patch it with an
  overlay module under `lua/` (loaded before the original), never edit the
  submodule.
- Import lua-in-types code by relative path
  (`../vendor/lua-in-types/src/aot/...`).

## The oracle (P1)

tslua under real Lua 5.4 (wasmoon) is the ground truth.

- `lua/tsc.lua`: the harness, `check(files, args) -> output, status`.
  Deterministic and free of io/os/debug/load/coroutines; it must also run on
  the lua-in-types reference interpreter and in the types.
- `scripts/tslua.ts`: runs a check in a fresh wasm instance. Instruction counts
  are exact (count hook of 1) and reproducible only because `Date.now` is
  frozen (Lua's string hash seed) and the instance is fresh with emscripten's
  `_` variable pinned (heap addresses decide `pairs` order over table keys).
  Outputs never depended on either.
- `vp run oracle` rewrites `oracle/expected/` and `oracle/manifest.json`;
  `vp run oracle -- --verify` reruns and compares outputs and counts.
- `vp run upstream` reselects `oracle/inputs/upstream/` (TypeScript cases);
  `vp run census` -> `docs/CENSUS.md`; `vp run profile` -> `docs/PROFILE.md`
  and `oracle/profile.json`; `vp run tower` -> `oracle/tower.json`; `vp run warmup` -> `oracle/warmup.json`.
- `oracle/inputs/**` is `-text` in `.gitattributes`: upstream cases keep their
  CRLF line endings byte for byte.

## tslua on the reference (P1 gate) and the boot image

- `scripts/luaref.ts`: the program (prelude + `oracle/modules.json`, the
  modules real Lua loads, + `lua/tsc.lua`) and the entry chunks `=boot`
  (`require("tsc")`) and `=check` (one check; INPUT and LIB are globals).
- `vp run ref` runs every input in both lib modes on the lua-in-types
  reference, compares with `oracle/expected/` byte for byte and writes
  `oracle/ref-manifest.json` (reference counters next to real Lua's
  instruction counts); `-- --image` restores each check from the boot image
  (`oracle/ref-image-manifest.json`); `-- --modules` rewrites
  `oracle/modules.json`.
- `vp run boot` writes `image/boot.<lib>.json` (git-ignored snapshots, see
  lua-in-types `docs/AOT.md`, "Snapshots") and `oracle/boot.json` (sizes):
  the state after `=boot`, `=cache` and a warm-up check, so the lib is
  already parsed and bound.
- The lib cache: `require("sourcecache").enable()` (lua/sourcecache.lua) makes the compiler
  host hand back the SourceFile an earlier check parsed (and bound) when its
  text is unchanged, as tsgo's watch host and parse cache do. Off by default
  (the oracle measures plain checks). `vp run libcache` verifies under real
  Lua that every output is unchanged with a warm cache (also with every input
  checked in sequence in one state) and records the cost in
  `oracle/libcache.json`.

## The image in types (P4)

- `vp run build` (`scripts/build-image.ts`): emits tslua from
  `image/boot.<lib>.json` with lua-in-types' `emitFromSnapshot` (entry
  `=check`, INPUT a type parameter, `drive: 4`, below the 50 lua-in-types suggests: see DRIVE). The program's code is
  identical for both lib modes, so it is written once (`image/tslua.prog.d.ts`,
  ~256 MB) and each lib gets its heap and start state (`image/tslua.<lib>.d.ts`:
  `S0<INPUT>`, `Step<S>`). Git-ignored; rebuild after a submodule bump.
- `src/index.ts`: `TS<>`/`TSMini<>` (hovers) and `TSStart`/`TSStep`/`TSOutput`
  (CLI chunks). `src/hover.ts` runs a check in one alias, refuelling from
  lua-in-types' fuel pool at a start and slots hashed from the source
  (tables in `src/hover.gen.ts`, `vp run gen:hover`). Keep its bindings flat:
  nested lookups (`P<P<P<A, c>, c>, c>`) made tsrs hang on the alias.
- `src/` and `examples/` load the image: excluded from the root tsconfig and
  from lint/format; `examples/tsconfig.json` is their project.
- `vp run gate:types` (`scripts/types-gate.ts`): oracle inputs through the
  CLI chunk form, compared with `oracle/expected/`; per-input entries and
  logs in `.run/gate/<lib>/`. `node scripts/hover.ts examples/hello.ts Out`
  hovers like an editor.
